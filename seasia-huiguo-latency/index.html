东南亚回国延迟实测：新加坡、曼谷、雅加达到国内各差多少

CN2东南亚回国延迟P0更新于 2026-11-05

光在光纤里每千公里大概五毫秒往返，加上设备和路由开销，实际大概是理论值的两倍。这是物理下限，任何线路都突破不了。按这个算，新加坡到广州直线距离约两千五百公里，理论往返二十五毫秒，行业里好线路普遍能到四十到五十毫秒。曼谷到广州更近一些，普遍三十五到四十五毫秒。雅加达最远，六十毫秒以内就算优秀。注意这些是行业普遍区间，不是单条线路的承诺值。你的入口在哪、落地在哪、走哪个运营商，都会让结果偏出这个区间，所以必须实测。

视频制作中

走香港中转和走公网中转的差

差距主要不在距离，在拥塞。走香港中转再进国内骨干，路径是固定的，晚高峰不参与公网拥塞，延迟基本稳定。走公网中转，路由是动态的，常见的情况是白天六十毫秒，晚上九点变成两百毫秒，还伴随丢包。

同一个城市，两种线路的差距能有三到五倍。这是行业普遍现象，不是某一家的数据，你那条线到底差多少，还得自己测出来才算数。

晚高峰才是真考场

测一条线路，别在上午测。上午所有线路都是好看的。要测就在晚九点到十一点测，这个时段是公网出口最挤的时候。测三个数：平均延迟、最大延迟、丢包率。平均延迟好看但最大延迟很高的，说明链路抖动大，一样不能用。

怎么自己测一组基准

方法给你。连续 ping 落地网关五百个包，记录平均、最大、最小和丢包。然后用路由追踪看跳数，正常情况下从东南亚到国内十到十四跳，超过二十跳说明绕路了。最后在不同时段各测一次，早中晚三次，画出来就知道这条线的真实水平。

把延迟分成四档

把延迟分成四档，自己对号入座。四十到六十毫秒，和在国内用没差别。六十到九十毫秒，日常使用无感，打游戏能玩。九十到一百五十毫秒，网页和视频没问题，实时操作开始有延迟感。一百五十毫秒以上，只适合看视频和下载，不适合任何实时业务。

这四档是按体感划的，不是按技术参数划的，你拿它去判断任何一条线路都成立。

延迟和可用性的取舍

延迟六十毫秒和八十毫秒，日常使用差别不大。但延迟六十毫秒丢包百分之五，和延迟八十毫秒零丢包，体验是天壤之别。丢包会触发重传，重传把延迟放大好几倍。所以选线路，先看丢包，再看延迟，顺序别反。

数据要自己攒

别人给的延迟数据参考价值有限，因为出口位置、本地运营商、时段都不一样。你自己攒一组数据，一个月测二十次，就有了基线。以后线路一变差，你立刻能看出来变了多少，而不是凭感觉说今天好慢。

一组可复现的测速脚本

延迟数据的价值在于「可对比」，所以测法必须固定：同一个目标、同样次数、同一时段。

#!/usr/bin/env bash
# 用法: ./lat.sh 目标IP 标签
target=$1; label=${2:-target}
for i in 1 2 3; do
  ping -c 30 -i 0.2 "$target" | tail -2 | head -1 | \
  awk -v l="$label" '{print l, "round="$i, $0}'
done
# TCP 层：更贴近真实业务
for i in 1 2 3; do
  curl -o /dev/null -s -w "tcp_connect=%{time_connect} ttfb=%{time_starttransfer} total=%{time_total}\n" \
    --max-time 10 "https://$target/"
done

记录四列就够：目标、时段、ICMP 中位数、TCP 建连中位数。攒两周数据，你就有了一份属于自己的基准，比任何评测文章都有用。

延迟和可用性的取舍

两条线路，一条 65ms 但每晚 22:00 抖到 150ms，一条 90ms 但全天稳定——后者更好。因为业务对「一致性」的敏感度通常高于「绝对值」：

  1. 网页浏览：绝对值重要，60ms 和 90ms 的体感有差
  2. 直播推流：一致性重要，抖动比延迟致命
  3. 远程桌面：两者都重要，但抖动导致的卡顿更难受
  4. 批量传输：绝对值几乎不重要，带宽和丢包才重要

所以选线路前先明确「你的业务最怕什么」，再去看对应的指标。

数据要自己攒

别人的评测只能当参考，原因有三个：内地各运营商的出口策略不同、你所在城市的最后一公里质量不同、服务商的线路会调整。三件事都会让别人的数字在你这里失效。

建议从第一天开始建一张表，每次测速追加一行。三个月后，你能清楚地看到「哪个月线路变差了」「换线路到底有没有改善」——这是唯一能支撑采购决策的数据。

一张自己维护的基准表

把测速结果固定成表格，长期才有比较价值：

日期时段落地RTT 中位数丢包备注
11-0121:30香港68ms0.3%正常
11-0221:30香港145ms4.2%疑似上游拥塞
11-0302:00香港62ms0%凌晨对照

第二行与第三行的对比就是「凌晨对照法」的作用：同一条线路，晚高峰 145ms、凌晨 62ms，说明问题在拥塞而不是线路本身。有这张表，跟服务商沟通时不用凭感觉，直接发数据。

几个常见的误判

  1. 「ping 新加坡比 ping 香港快」→ 那是 ping 到落点，不是 ping 到内地。要看的是「经中转回内地」的总延迟
  2. 「白天 60ms 所以线路很好」→ 白天不拥塞，晚高峰才是考场
  3. 「丢包 5% 一定是线路差」→ 先排除本地 WiFi 与最后一公里
  4. 「延迟低就一定流畅」→ 抖动大时，低延迟也会卡

四个误判的共同点是「只看一个数字」。真实体验由延迟、抖动、丢包三者共同决定。

一个判据：延迟随人数变化

同一条线路，一个人用时 65ms、三个人同时用时 140ms，说明带宽或并发能力不足（超售型）。一个人用时也波动到 140ms，说明是链路拥塞（时段型）。这个对比五分钟能做完，比任何测速都直接。

一个采样建议

每次测速至少 30 个包，少于 30 个的样本会被单次抖动带偏。时段上，晚高峰与凌晨各测一次，两组数据一起看，才能区分「线路本身」与「拥塞」。只有一组数据时，任何结论都站不住。
