小火箭分流规则：按域名和按 IP 到底差在哪

代理协议小火箭分流规则P1更新于 2026-11-05

小火箭里的规则分三类：域名规则、IP 规则、还有最终兜底规则。域名规则匹配你访问的域名，IP 规则匹配目标地址，兜底规则决定没命中的流量怎么办。三类的匹配顺序是域名优先，然后是 IP，最后兜底。搞清这个顺序，规则为什么没生效就好判断了。

视频制作中

域名规则的写法

域名规则有三种写法。完全匹配，只匹配这一个域名。后缀匹配，匹配这个域名和它下面所有子域名，这个最常用。关键字匹配，域名里包含这个词就命中，最宽泛也最容易误伤。日常用后缀匹配就够了，关键字匹配尽量别用，宁可在规则里多写几条。

按 IP 的规则为什么容易漏

因为一个网站的资源往往不在同一个地址上。你访问的主域名走专线了，图片和视频在另一个 CDN 域名上，那个域名没写规则，走的是本地。结果就是页面打开了，图片刷不出来，视频一直转圈。这不是线路问题，是规则覆盖不全。

规则写重了会怎样

同一个域名被两条规则命中，走的是排在前面的那条。如果你把一条宽泛的规则放在前面，后面精心写的规则全都不会生效。表现是无论怎么改后面的规则，效果都不变。所以写完规则一定要按顺序看一遍，把具体的放前面。

兜底规则怎么定

兜底有三种：直连、代理、拒绝。日常用建议选直连，这样没写规则的流量不会莫名走到专线上，专线带宽留给真正需要的。缺点是漏掉的网站你发现不了。另一个做法是先用代理做兜底观察一周，看日志里都有哪些域名在走，把该直连的挑出来写规则，再改成直连兜底。

怎么验证规则生效

小火箭里有连接日志，能看到每条连接命中了哪条规则、走的是哪个节点。这是最可靠的验证方式。对着日志看三条：该走专线的域名是不是命中了专线节点，走本地的是不是没走节点，有没有你没见过的域名在走专线。

看完一遍，规则就心里有数了。

规则的匹配顺序

小火箭按「从上到下，命中即止」匹配。这意味着规则顺序本身就是逻辑，顺序错了规则写得再全也没用：

  1. 具体规则在前（单域名、单 IP）
  2. 分组规则在中（域名后缀、关键词）
  3. 兜底规则在最后（GEOIP、FINAL）

典型错误是把 `GEOIP,CN,DIRECT` 放在最前面。结果所有国内 IP 先命中直连，后面的代理规则一条都轮不到——表现为「节点正常但某些站打不开」。

三种规则类型的实际差异

类型匹配对象命中时机常见坑
DOMAIN-SUFFIX域名后缀需要能看到域名（TLS SNI 或 HTTP Host）用 IP 直连的应用无法命中
IP-CIDR目标 IP任何流量CDN 会让同一域名解析到多个 IP，需要 `no-resolve` 控制
GEOIPIP 的归属库任何流量库的更新滞后，新段可能判错

`IP-CIDR` 后面的 `no-resolve` 参数很关键：不加它，客户端为了判断规则会去做 DNS 解析，导致「规则判断本身就产生了一次国内 DNS 查询」——既是泄漏源，也是延迟源。

规则写重了会怎样

重复的规则不会报错，只会让第一条生效，后面的被静默跳过。危害是排查时你以为「我明明写了这条」，实际生效的是更早的那条。

维护建议：

  1. 每条规则写注释，标明为什么加
  2. 定期用「删除后测试」的方式清理：删掉可疑规则，看行为是否变化
  3. 不要囤积规则集，只保留会实际用到的

验证规则是否生效

最可靠的方法是看实际出口，而不是看规则文本：

  1. 打开目标站点，然后到 IP 回显页看出口 IP
  2. 用「只走代理」和「只走直连」两个模式对比同一站点的加载速度
  3. 观察 DNS：如果目标域名在直连模式下也解析到了远端节点，说明解析被规则影响了

第二条的判读经验：走代理明显更快 → 说明该站点确实需要代理，规则对了；走直连更快 → 说明这条规则不该加。

规则集不要贪多

社区规则集的通病是「覆盖广但互相冲突」。导入三套规则集之后，同一个域名可能同时命中三条不同策略，实际生效的是最前面那条——而你不知道那是哪一条。

可控的做法是：只保留一套主规则集，加上自己手写的少量规则（放在最前面）。手写规则的数量控制在 20 条以内，每一条都有明确理由。这样出问题时，排查范围是可控的。

判断规则集是否过大：文件超过 5MB、条目超过 5 万，通常已经超出个人使用的需要，且会拖慢启动与匹配。

一条最小可用规则集

新手可以从这六行开始，够用且不易出错（顺序即优先级）：

DOMAIN-SUFFIX,google.com,PROXY
DOMAIN-SUFFIX,youtube.com,PROXY
DOMAIN-KEYWORD,openai,PROXY
IP-CIDR,8.8.8.8/32,PROXY,no-resolve
GEOIP,CN,DIRECT
FINAL,PROXY

六行之后，再按实际需要往里加。每加一条都要能回答「为什么需要这条」——回答不出来的，大概率不需要。
