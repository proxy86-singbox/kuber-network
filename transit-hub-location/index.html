中转仓选址：香港、新加坡、日本落地差在哪

线路中转仓选址P2更新于 2026-11-05

中转的逻辑是，先把流量从你所在的国家送到一个中转点，再从那里走优质线路回国。中转点选在哪，决定了后面那一段的路径质量。选择的标准不是距离最近，而是这个点和国内之间的线路质量够不够硬。

香港中转的优势

香港是目前回国路径最成熟的中转点。原因有两个。第一，到广州深圳的物理距离近，延迟基数低。第二，香港到国内的优质线路选择多，CN2 的入口在香港比较集中。东南亚回国走香港中转，延迟通常能压到四十到七十毫秒，晚高峰也稳。

新加坡适合什么场景

新加坡的优势是辐射整个东南亚，印尼、马来西亚、泰国的用户接过来距离都不远。缺点是到国内的物理距离比香港远，延迟基数高一些。适合用户分布在整个东南亚的情况，用统一的中转点降低运维复杂度。

日本为什么被低估

日本到国内北方的路径质量很好，尤其是到上海、北京方向。如果你的用户主要在国内北方，日本落地可能比香港更优。缺点是到南方的延迟略高。所以落地选择要看你的目标用户在哪个区域，不是一刀切。

怎么自己测出更优解

方法是从你的所在地，分别向三个落地点的测试地址做追踪和延迟测试，各测三个时段。比较三个数：平均延迟、最大延迟、丢包率。然后用落地点的地址再往国内目标做一次追踪，看后半段的路径质量。两段加起来才是全程。

多落地比单落地稳

有条件的话，两个落地点互为备份。主用的那条线出问题时切到备用，切换时间控制在几秒内。对养号和直播来说，稳定的可切换性比单条线路的极限性能更重要，因为你最怕的是断，不是慢。

三地落地的对照

落地到内地典型 RTT到东南亚源站优势劣势
香港15-40ms（GIA）20-50ms物理最近，CN2 资源足成本最高，IP 段较拥挤
新加坡45-80ms（经香港）5-20ms东南亚枢纽，国际带宽便宜回国需经香港或日本中转
日本东京30-60ms40-70ms到北方快，国际带宽充足到华南绕路，晚高峰波动

选择逻辑不是「哪个最好」，而是「源站在哪、用户在哪」：

  1. 源站在东南亚、用户在内地全境 → 香港落地（最优）
  2. 源站在东南亚、主要是本地业务 → 新加坡落地，回国流量单独走香港
  3. 源站在东北亚、用户在内地北方 → 东京落地

多落地为什么比单落地稳

单点落地的问题是：一旦这条线路晚高峰拥塞，你没有备选。多落地的价值在于可切换：

  1. 主用香港 GIA：延迟最低
  2. 备用日本或新加坡：主线路故障时切过去，延迟上升但业务不断
  3. 切换用 DNS 或客户端规则实现，不需要改代码

成本上，多落地不是简单翻倍：备用线路可以用便宜得多的 GT 或 CMI，只在故障时启用。

怎么自己测出更优解

# 对三个落地各跑一轮，同一时段、同一目标
for h in hk.example.com sg.example.com jp.example.com; do
  echo "== $h"
  ping -c 30 -i 0.2 "$h" | tail -2 | head -1
  curl -o /dev/null -s -w "ttfb=%{time_starttransfer} total=%{time_total}\n" "https://$h/"
done

关键纪律：三个落地必须在同一时段测（最好同一分钟内），否则数据不可比。晚高峰测一次、凌晨测一次，两组数据就能看出「谁在拥塞时更稳」。

落地之后还要看什么

落地只是物理位置，实际质量还取决于三件事：

  1. 上游带宽是谁家的（决定晚高峰是否拥塞）
  2. 与内地运营商的互联关系（决定走 CN2、CMI 还是公网）
  3. 机房自身的稳定性（决定会不会整段掉线）

所以「香港落地」不等于「香港好线路」。同样在香港，GIA 与 GT 的晚高峰表现能差三倍——这一点在 CN2 那两篇里有完整的判定方法。

一个常被忽略的成本项：回程

落地选址时大家看「去程延迟」，但实际体验由回程决定的部分同样多——尤其是你从内地访问境外服务时，回程才是主路径。

判断方法：分别在两端跑 mtr，对比两边的路径长度与拥塞点。有的线路去程走 CN2、回程走 163，白天看不出差别，晚高峰回程先崩。

这就是为什么「双向测试」在选址阶段就该做，而不是等上线后出问题再查。

选址的决策清单

  • 源站在哪？决定物理下限
  • 主要用户在哪？决定回程质量要求
  • 业务怕延迟还是怕抖动？直播怕抖动，网页怕延迟
  • 预算能否覆盖 GIA？不能就先上 GT/CMI，把晚高峰的期望值调低
  • 是否需要备用落地？需要就选一个便宜的 GT 作备份
  • 谁来做双向测试？没有数据就不要拍板

六问答完，选址基本确定。剩下的差异，靠实测数据修正。

一句总结

选址的本质是「把物理距离换成钱」：距离越近延迟越低，成本越高。选型的正确姿势是先算出「你的业务能接受多少延迟」，再在这个约束下找最便宜的落地。反过来（先看价格再看延迟）通常会买到用不了的东西。

一个落地之后还要盯的指标

落地选完不是结束。上线后每周看三项：晚高峰延迟中位数、丢包率、以及「目标平台是否出现新的验证」。前两项衡量线路，第三项衡量 IP 信誉。三者任一恶化，就进入换线路或换 IP 的流程，而不是等出问题再救。
