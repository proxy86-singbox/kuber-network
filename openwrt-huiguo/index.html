OpenWrt 配 L2TP 回国：装包、建接口、防火墙三步走通

软路由OpenWrt回国P0更新于 2026-11-05

先说依赖。OpenWrt 要跑 L2TP 客户端，需要四个包：xl2tpd 是拨号进程，kmod-l2tp 和 kmod-l2tp-eth 是内核模块，ppp-mod-pppol2tp 是 PPP 那边的支持。这些在官方源里都有，用 opkg 装就行。装完重启一次，不重启模块不一定加载上，很多人卡在这。

视频制作中

建接口填什么

在网络接口里新建一个协议选 L2TP 的接口。服务器地址填服务商给的域名或者 IP，用户名密码照填。重点在高级设置里两项：一是把默认路由的勾去掉，二是保持连接打开，重连间隔设成十秒。

默认路由这个勾，勾了就是全局走专线，不勾就是靠后面配分流。先别勾，等通了再说。

防火墙要单独划区

这一步最容易漏。新接口建好之后，默认在防火墙里是没有归属的，流量出不去也进不来。正确做法是把这个接口单独划一个防火墙区域，输入接受，输出接受，转发接受，然后打开伪装。不打开伪装的话，局域网里的设备拿着内网地址出去，对端不知道怎么回你。

分流的两种做法

分流有两个思路。第一个是按域名，适合只需要特定平台走专线的场景，配好域名列表，命中的流量走这个接口。第二个是按目标地址，适合需要整片区域走专线的情况。两种可以一起用，但要注意优先级，域名规则一般先匹配，所以别在两边都写同一条规则，会打架。

DNS 设在哪一层

DNS 是关键。如果你的域名解析走的是本地运营商，那就算流量走了专线，平台也知道你人在哪。做法是把 DNS 请求也转发到落地端，或者用支持分流解析的插件，让国内域名用国内 DNS，跨境域名用落地端 DNS。

验证方法是拨通之后查一下解析服务器地址，看是不是落地那边的。

不通时的排查顺序

拨不上按这个顺序查。第一，看日志里有没有发送和接收，只有发送没有接收，多半是对端地址或者端口被挡。第二，检查本地网络有没有封掉 UDP 一千七百零一。第三，确认用户名密码和服务商给的一致，注意大小写。

第四，看防火墙有没有把这个接口的流量挡了。按这个顺序走，基本三步内能定位。

通了之后的验收

拨通不等于可用。验收三件事。一，在局域网里的电脑上查出口 IP，应该是落地端的地址，不是本地地址。二，连续 ping 落地网关三百个包，丢包率应该是零，延迟波动小于二十毫秒。三，打开一个国内的视频网站看能不能正常加载。

这三条都过，才算配好。
