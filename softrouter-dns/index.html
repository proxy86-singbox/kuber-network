软路由 DNS 怎么设：解析走本地还是走专线

软路由软路由DNSP2更新于 2026-11-05

说个很多人不知道的事。现在大部分平台用智能调度，你从哪个地区发起解析，它就返给你最近的服务器地址。你人在东南亚，解析请求也从东南亚发出去，返回的就是东南亚的节点。这个节点不认你的专线出口，于是你明明连着专线，访问还是慢。

视频制作中

三种配置模式

第一种，全部 DNS 走本地运营商。最快，但解析结果不受控，适合只访问本地服务。第二种，全部 DNS 转发到落地端。结果最准，但所有解析都绕一圈，本地服务反而变慢。第三种，分流解析，国内域名用国内 DNS，境外域名用落地端 DNS。

三种里第三种最平衡，也最费配置功夫。

怎么验证有没有泄漏

验证方法很直接。打开 DNS 检测网站，看它给出的解析服务器地址列表。如果列表里全是你本地运营商的地址，说明解析完全在本地。如果出现落地端的地址，说明转发生效了。再看解析结果里的地理信息，是不是和你期望的地区一致。

常见配置错误的三个表现

第一个表现，网页能打开但特别慢，打开开发者工具看时间，时间都花在等待响应上，这是解析绕路。第二个表现，部分网站打不开，提示找不到服务器，这是 DNS 转发链路断了。第三个表现，同一个网站时快时慢，这是两条 DNS 在交替应答。

最小改法

不想折腾的话，改法可以很小。只把需要走专线的那些域名，单独指定用落地端 DNS 解析，其他域名不动。这样改动面最小，风险最低。做法是在软路由的 DNS 配置里加域名转发规则，或者用支持按域名指定上游的解析插件。

缓存要清

改完 DNS 一定清缓存，不清你测的还是旧结果。清两个地方，软路由本地的解析缓存，还有客户端系统里的缓存。清了再测，不然你会以为改的没生效，然后反复改，越改越乱。

三种 DNS 模式的对照

模式谁在解析优点风险适合
全部走本地国内运营商 DNS快、简单境外站点解析到国内 CDN 或污染结果只做国内访问
全部走专线落地城市的 DNS解析与出口一致国内站点会被解析到远端节点，反而变慢几乎不用国内网
分流解析按域名选上游兼顾两边配置复杂，规则要维护主流方案

分流解析的判断依据有两个：域名后缀（`.cn`、已知国内站点列表）与解析结果（返回的 IP 是否属于国内段）。前者简单但会漏（很多国内服务用 .com），后者准确但多一次判断。

最小可行配置（dnsmasq）

# /etc/config/dhcp → config dnsmasq
option domainneeded '1'
option boguspriv '1'
option localise_queries '0'
option rebind_protection '0'
option noresolv '1'
list server '223.5.5.5'          # 默认：国内
list server '/google.com/10.0.0.1'   # 指定：专线侧解析器
list server '/youtube.com/10.0.0.1'
list server '/openai.com/10.0.0.1'

`noresolv '1'` 是关键：不加它，dnsmasq 会去读 /etc/resolv.conf，绕过你的 server 列表，表现为「配了但没用」。

`localise_queries '0'` 也重要：它关掉「按来源改写解析」的行为，避免与分流规则打架。

三种典型的配置错误表现

  1. 「配了 server 但没生效」→ 忘了 `noresolv 1`，或者有第二条 dnsmasq 在跑（常见于同时装了 adguardhome）
  2. 「境外站点打开很慢，但 ping 通」→ 解析到了远端 CDN 节点，检查该域名的解析上游
  3. 「国内站点偶发解析失败」→ 上游只给了专线 DNS，专线侧对国内域名返回 NXDOMAIN；给国内域名单独指定上游

验证与缓存

# 看某个域名实际由谁解析
dig @127.0.0.1 youtube.com +short
dig @127.0.0.1 www.qq.com +short

# 看 DNS 请求走哪条出口（在软路由上抓）
tcpdump -i ppp0 -n port 53 -c 10
tcpdump -i br-lan -n port 53 -c 10

改完配置一定要清缓存：`/etc/init.d/dnsmasq restart` 之后，客户端侧也要清（浏览器、系统、iOS 的 DNS 缓存都独立）。不清缓存时你会看到「旧结果还在」，误判成配置没生效。

分流 DNS 的一个实用规则：按解析结果再判一次

只按域名后缀分流会漏掉大量情况（很多国内服务用 .com 域名）。补一层「按解析结果判断」能覆盖大部分漏网：

# dnsmasq 不支持按结果分流，用 smartdns 的规则更直接
# smartdns.conf
nameserver /cn/223.5.5.5
nameserver /proxy/10.0.0.1
# 或者用 ipset 联动：国内段命中则直连
ipset /cn/chnroute

实际部署里，最稳的组合是「域名后缀分流（覆盖已知的）+ 目的地址分流（覆盖剩余的）」。两层叠加后，漏判率能从两成降到个位数百分比。

三种解析器方案的取舍

方案优点缺点建议
dnsmasq（内置）零成本、稳定分流能力弱，只能按域名指定上游起步用
smartdns支持按结果分流、多上游测速配置项多，容易配错中型场景
AdGuardHome界面友好、带广告过滤资源占用较高，分流能力弱于 smartdns需要过滤时

选择原则：先看「是否需要按解析结果分流」。需要 → smartdns；只需要按域名 → dnsmasq 够；需要广告过滤 → AdGuardHome 叠加在前面。三者可以叠加部署，但要注意「谁监听 53」，同时只应有一个。

一个容易忽略的细节：DNS 与策略路由的方向

DNS 请求是「你发出、上游返回」，方向与业务流量一致。如果策略路由只对「出方向」做了标记而没处理回程，DNS 会走错出口。检查方法是 `tcpdump -i 任一接口 port 53` 看请求与响应是否走同一路径。不一致时，按 DNS 服务器地址单独加一条策略路由即可。

一个排障捷径

DNS 问题占「配好但不通」的一半以上。最快的定位方法不是看配置，而是看结果：在客户端上 `nslookup 目标域名 你的路由器IP`，如果返回的 IP 明显属于远端节点而目标服务在国内，说明上游选错了。改上游比改规则快。
