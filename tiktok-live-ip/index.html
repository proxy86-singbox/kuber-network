TikTok 直播带货的 IP 要求：上行带宽和抖动到底怎么算

直播TikTok直播IPP0更新于 2026-11-05

先说一个很多人搞混的事。短视频是上传完就结束了，中间可以重传、可以排队，网络抖一下你根本感觉不到。直播不行，直播是持续的实时上行，这一秒的数据掉队了，观众那边就是黑一下、卡一下。所以你养短视频号用的那套网络，未必撑得住直播。

视频制作中

上行带宽怎么算

算法很简单。先定你 OBS 里的推流码率，一零八零 p 三十帧一般是四千五到六千 kbps，一零八零 p 六十帧要到八千。然后加冗余，冗余按码率的百分之五十算。也就是说六千码率，你上行至少要九兆。

留这一半是给瞬时峰值和重传的，不留，一遇到网络波动立刻掉帧。

抖动比延迟更致命

第二个指标是抖动。延迟两百毫秒其实能播，观众最多觉得互动慢半拍。但抖动一旦超过八十毫秒，画面就会一顿一顿。因为直播的接收端缓冲只有一两秒，抖动把它吃完了就开始卡。所以测一条线路，你看的不该是平均延迟，而是延迟的最大值和最小值差多少。

直播 IP 必须静态独享

第三点，直播用的 IP 必须是静态的、独享的。静态是因为推流过程中 IP 一变，连接直接断，观众看到的就是直播结束。独享是因为共享 IP 上别人在跑什么你控制不了，平台的风控会把整个 IP 上的行为算在一起。

你推流一切正常，号却被压流量，问题就在这。

开播前十分钟测三项

具体怎么测。开播前十分钟做三件事。第一，用测速工具看上行实测值，要稳定在你码率的一点五倍以上。第二，连续 ping 你的落地网关三百个包，看丢包率和最大延迟。第三，OBS 里开统计面板，看 dropped frames 这个数字，只要开播五分钟内它开始涨，说明这条链路撑不住当前码率。

卡顿出现在两分半说明什么

有个很典型的故障特征。如果直播每次卡顿都出现在开播两分半左右，那不是网络突然变差，是缓冲被慢慢吃空了。原因通常是码率设太高，或者链路的实际带宽比你以为的低。处理办法不是换线路，先把码率降百分之三十再试。

降完不卡了，就是带宽问题，不是线路问题。

该怎么配

配置上的建议是这样。一条独享静态 IP 走专线回国方向给直播用，码率按实测上行的六成设，OBS 的输出模式选固定码率，别选动态。手机端直播的话，先确认手机连的是软路由下发的那条线，不是自动切到了本地网络。

这一步错了，你后面所有测试都没意义。

上行带宽的实测公式与工具

口播里给了算法，这里给可直接执行的版本。直播上行需求的估算式：

所需上行(Mbps) = 推流码率 × (1 + 冗余系数)
冗余系数取 0.5 ~ 1.0
1080p30 直播：码率 4.5-6 Mbps → 需 7-9 Mbps 稳定上行
720p30 直播：码率 2.5-3 Mbps → 需 4-6 Mbps 稳定上行
竖屏 1080p 直播：码率 3-5 Mbps → 需 5-7 Mbps 稳定上行

「稳定上行」和「峰值上行」是两件事。运营商宣传的 100M 上行是峰值，直播要的是「连续 30 分钟不低于 X」。测法是持续上传而不是几分钟的测速：

# 持续 60 秒上传，看速度是否掉下来
curl -o /dev/null -w "速度 %{speed_upload} B/s  总耗时 %{time_total}s\n" \
  -T 大文件路径 https://你的测试上传端点

跑三次，取最差的一次作为你的「可用上行」。秋千式的数字（前 10 秒 30M、之后 5M）说明有突发限速（burst），直播会在两分钟后开始卡。

抖动（jitter）为什么比延迟更致命

延迟高表现为「观众那边延迟大一点」，抖动大表现为「画面一顿一顿」。因为直播是等时流：这一帧必须在 40 毫秒内到达，晚到的帧就是废帧。

抖动的量化方法是连续 ping 取标准差：

ping -c 100 -i 0.2 你的推流端点 | tail -3
# 输出里的 mdev/avg 就是抖动指标
# mdev < 5ms 优秀，5-15ms 可用，> 30ms 直播必然卡

mtr 也能看每跳的抖动（StDev 列）。如果抖动是在某一跳突然变大并保持，问题在那一跳之后；如果全程均匀地大，问题在本地线路或 WiFi。

推流参数的配合

网络侧调好之后，推流参数也要匹配，否则好线路也白瞎：

场景码率关键帧间隔编码说明
4G/弱网1.5-2.5 Mbps1 秒H.264优先保连通性
家宽+独享IP4-6 Mbps2 秒H.264/H.265主流配置
高画质带货6-8 Mbps2 秒H.265需 10M 以上稳定上行

关键帧间隔设 1 秒的代价是码率上升 20% 左右，收益是观众中途进入时首帧快。带货直播建议 1-2 秒，不要 4 秒以上。

卡顿的时间线诊断

同一个「卡」，发生在不同时间点，原因完全不同：

  • 开播 10 秒内卡：握手与首帧传输，检查 MTU 与上行峰值
  • 卡在 2 分 30 秒左右：突发额度用尽，被限速到基础速率（最常见）
  • 卡在固定时段（比如每晚 21:30）：线路拥塞，不是你的问题
  • 随机零散卡：抖动或丢包，查 WiFi 与最后一公里
  • 只有部分观众卡：观众侧问题或 CDN 边缘节点问题

这张表的价值在于：不用改任何配置就能判断该找谁。2 分半卡是运营商限速，换线路；21:30 卡是拥塞，换更好的线路（CN2 GIA）；零散卡先查家里的 WiFi 和路由器。
