TikTok 直播带货的 IP 要求：上行带宽和抖动到底怎么算

直播TikTok直播IPP0更新于 2026-11-05

先说一个很多人搞混的事。短视频是上传完就结束了，中间可以重传、可以排队，网络抖一下你根本感觉不到。直播不行，直播是持续的实时上行，这一秒的数据掉队了，观众那边就是黑一下、卡一下。所以你养短视频号用的那套网络，未必撑得住直播。

视频制作中

上行带宽怎么算

算法很简单。先定你 OBS 里的推流码率，一零八零 p 三十帧一般是四千五到六千 kbps，一零八零 p 六十帧要到八千。然后加冗余，冗余按码率的百分之五十算。也就是说六千码率，你上行至少要九兆。

留这一半是给瞬时峰值和重传的，不留，一遇到网络波动立刻掉帧。

抖动比延迟更致命

第二个指标是抖动。延迟两百毫秒其实能播，观众最多觉得互动慢半拍。但抖动一旦超过八十毫秒，画面就会一顿一顿。因为直播的接收端缓冲只有一两秒，抖动把它吃完了就开始卡。所以测一条线路，你看的不该是平均延迟，而是延迟的最大值和最小值差多少。

直播 IP 必须静态独享

第三点，直播用的 IP 必须是静态的、独享的。静态是因为推流过程中 IP 一变，连接直接断，观众看到的就是直播结束。独享是因为共享 IP 上别人在跑什么你控制不了，平台的风控会把整个 IP 上的行为算在一起。

你推流一切正常，号却被压流量，问题就在这。

开播前十分钟测三项

具体怎么测。开播前十分钟做三件事。第一，用测速工具看上行实测值，要稳定在你码率的一点五倍以上。第二，连续 ping 你的落地网关三百个包，看丢包率和最大延迟。第三，OBS 里开统计面板，看 dropped frames 这个数字，只要开播五分钟内它开始涨，说明这条链路撑不住当前码率。

卡顿出现在两分半说明什么

有个很典型的故障特征。如果直播每次卡顿都出现在开播两分半左右，那不是网络突然变差，是缓冲被慢慢吃空了。原因通常是码率设太高，或者链路的实际带宽比你以为的低。处理办法不是换线路，先把码率降百分之三十再试。

降完不卡了，就是带宽问题，不是线路问题。

该怎么配

配置上的建议是这样。一条独享静态 IP 走专线回国方向给直播用，码率按实测上行的六成设，OBS 的输出模式选固定码率，别选动态。手机端直播的话，先确认手机连的是软路由下发的那条线，不是自动切到了本地网络。

这一步错了，你后面所有测试都没意义。
