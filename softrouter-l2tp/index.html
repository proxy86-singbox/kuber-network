iKuai 软路由用 L2TP 拨号回国：完整配置，全屋设备自动走

软路由软路由IPP0更新于 2026-11-05

这期讲 iKuai 软路由怎么用 L2TP 拨号回国。为什么选 L2TP？因为路由器原生支持，不用装任何客户端，全屋设备自动走。电视盒子、Switch、iPad、智能音箱，一台台配太麻烦，L2TP 一次搞定。

第一步 新增 WAN 口

第一步，网络设置，内外网设置，新增一个 WAN 口。如果你的软路由只有一个物理网口空闲，就选基于物理网卡的混合模式。如果有空闲网口，直接选物理网卡。

第二步 填 L2TP 参数

第二步，接入方式选 L2TP。填服务器地址、用户名、密码，这三个是服务商给你的。服务器地址可以是域名也可以是IP。填完之后先别急着保存。

第三步 关键的那个勾

第三步，高级设置里有个选项叫使用默认网关，必须勾上。这个是最容易漏的一步。不勾的话，拨号是成功的，状态显示已连接，但流量根本不走隧道。很多人卡在这里一整天。

第四步 分流

第四步，分流设置。把国内IP段设为直连，其余走 L2TP。不分流的话，你访问国内网站也绕一圈，反而变慢。iKuai 自带运营商地址库，直接用就行。

常见错误

常见错误有三个。第一，拨号成功但上不了网，检查默认网关有没有勾。第二，能上网但国内网站变慢，检查分流规则。第三，连接一直断开，L2TP 走 UDP 五百和一千七百零一端口，部分网络环境会拦，这时候改用 VLESS。

为什么软路由要选 L2TP

家里设备一多，逐台装客户端这件事就不可行了。电视盒子、Switch、iPad、智能音箱、扫地机器人，这些东西有的不能装客户端，有的装了也不会用。

L2TP 的价值是「路由器拨号、全屋共享」：软路由作为一台设备拨出去，NAT 后面的所有终端自动继承这条隧道，不需要任何客户端，不需要任何配置。这就是它在家庭场景里不可替代的原因。

VLESS 更适合单机精细控制，两者的分工在「L2TP 还是 VLESS」那篇里讲透了。这篇只讲 iKuai 上怎么把 L2TP 跑通。

完整配置步骤

第一步：新增一个 WAN 口

路径是「网络设置 → 内外网设置 → 点击空闲网口 → 接入方式」。两种接法：

  • 有物理空口：直接绑定物理网卡，最稳，性能最好
  • 只有一个网口空闲或做了单臂路由：选「基于物理网卡的混合模式」，在这个网口上同时跑 PPPoE 和 L2TP

混合模式要注意：一个网口上跑多条链路时，iKuai 用 VLAN 或 MAC 区分，配置好后在「物理网卡」列表里能看到多个虚拟接口。如果这里配错，表现是拨号一直重试但没有任何日志。

第二步：接入方式选 L2TP，填参数

字段填什么常见错误
服务器地址域名或 IP，域名更好（换 IP 不用改配置）填了带端口的地址
用户名服务商给的账号前后多了空格
密码服务商给的密码特殊字符在网页端被转义
预共享密钥若服务商启用 IPsec留空但服务端要求，表现为「无响应」

这里的顺序值得强调：先保存为一个不启用的 WAN，再去高级设置里改选项，最后启用。因为部分 iKuai 版本在启用状态下改高级选项，会有配置不生效的情况。

第三步：勾上「使用默认网关」——最容易漏的一步

高级设置里有「使用默认网关」这个勾选项，必须勾上。

不勾的后果非常典型：拨号显示已连接、拿到对端分配的地址、日志里一切正常，但流量完全不进隧道。很多人卡在这一步一整天，因为所有状态指示都是绿的。

原理很简单：不勾「使用默认网关」时，这条 WAN 只注册了一条明细路由（只有对端网段走它），默认路由仍然指向主 WAN。你的终端访问互联网走的是主 WAN，隧道只被用来访问隧道对端本身。

如果确实需要「只让部分设备走隧道」，那就保持不勾，改为在分流里用源地址策略指定设备。这是进阶用法，先把默认网关跑通再折腾。

第四步：设置 MTU

L2TP 的封装会增加额外开销（L2TP 头 + PPP 头 + 可能的 IPsec ESP 头）。默认 1500 的 MTU 在多数跨境链路上会导致大包被丢，表现是：

  1. ping 小包正常
  2. 打开网页首页能出，图片加载到一半卡住
  3. SSH 能连上但传输大文件时挂起

正确做法是测出路径 MTU：

# Linux / macOS 上带 DF 标志逐步减小包长，找到不分片的最大值
ping -c 3 -D -s 1400 你的隧道对端地址
ping -c 3 -D -s 1372 你的隧道对端地址

找到不分片的最大包长后减 28（IP+ICMP 头）就是可用 MTU。实战中直接设 1400 或 1420 都能解决绝大多数问题。iKuai 里的位置在 WAN 口的高级设置里。

第五步：分流

不分流是最常见的性能问题。所有流量都走隧道，访问国内网站也要绕一圈香港，结果比直连更慢。

iKuai 的分流逻辑是「策略路由」：

  • 目的地址属于国内运营商地址库 → 走主 WAN（直连）
  • 其余 → 走 L2TP 隧道

配置路径在「流控分流 → 分流设置 → 端口分流/域名分流」。国内地址库用系统自带的即可，iKuai 会定期更新。

分流之后要做验证，方法是同时开两个窗口：

# 应该显示你的国内直连 IP
curl -s https://myip.ipip.net
# 应该显示隧道出口 IP
curl -s --interface ppp0 https://myip.ipip.net

如果两个结果都是隧道 IP，说明分流没生效；如果都是直连 IP，说明默认网关没勾或隧道没起来。

第六步：掉线自动重连与双 WAN 主备

L2TP 走 UDP，跨境链路上偶发丢包会导致隧道假死（状态显示已连接但实际不通）。两个配置能显著改善：

  • 开启「线路检测」，用 ping 或 HTTP 探测隧道对端，连续失败自动重拨
  • 配置主备：主 WAN 是本地宽带，备 WAN 是 L2TP，主 WAN 断线时自动切换

假死和断线的区别：假死时接口状态是 up，但业务不通。检测方式要选「业务探测」而不是「接口状态」。

安全加固（很多人跳过）

软路由一旦被当成跳板，损失比账号更大。三条必做：

  • 关闭 WAN 侧的管理页面访问（「系统设置 → 远程访问」里限制来源）
  • 改掉默认的管理端口和默认密码，管理密码 16 位以上
  • 关闭 UPnP，除非确实需要（它会把你内网的端口暴露出去）

什么时候该放弃 L2TP 换 VLESS

三个信号：

  1. 拨号经常失败，日志显示对端无响应——UDP 被拦，换协议比调参数有效
  2. 需要按应用分流（比如只有某个 App 走隧道），L2TP 做不到
  3. 所在网络对 L2TP 特征有识别（部分企业网、校园网）

替换方案是软路由上跑 VLESS/VMess 客户端插件（OpenWrt 用 passwall/shellcrash，iKuai 用 docker 跑 sing-box），逻辑一样是「路由器拨出去、全屋共享」，只是协议换了。

配置完成后的验证清单

  • 隧道接口状态 up，且持续 30 分钟不掉
  • 国内网站直连（curl 回显为本地 IP）
  • 境外网站走隧道（curl 回显为隧道 IP）
  • 大文件下载不中断（验证 MTU）
  • 晚高峰 21:00 复测一次延迟与丢包
  • 重启软路由后自动重连

状态灯全绿但业务不通，先看这三个日志

iKuai 的 L2TP 问题多数不需要抓包，看三处日志就能定位：

  1. 系统日志里的 pppd 记录：出现 `LCP: timeout sending Config-Requests` 说明对端没回应（端口被拦或地址错）；出现 `CHAP authentication failed` 说明账号密码不对
  2. 线路检测记录：显示接口 up 但探测失败，属于典型的隧道假死
  3. 防火墙日志：出现大量来自隧道地址段的丢弃记录，说明策略路由或 NAT 规则把回程流量挡了

隧道假死和真断线的区别值得记住：假死时接口状态是 up，系统以为一切正常，但业务不通。所以线路检测必须选「业务探测」（ping 或 HTTP），选「接口状态」等于没检测。

转发性能的瓶颈在哪

软路由跑 L2TP 时，性能瓶颈通常在三个地方，按出现频率排：

  1. 单核加密：IPsec 的加密在单核上完成，N 核 CPU 也只有一核在跑，200Mbps 左右就会看到某一核满载
  2. 内存带宽：小包转发场景（大量短连接）比大包更吃内存带宽
  3. 网卡队列：虚拟化环境里网卡中断集中在单队列，需要开多队列或启用 virtio 优化

判断方法很简单：跑满速时看 `top` 里是否有单核 100%。是单核满 → 加密瓶颈；是全程空闲但速度上不去 → 上游限速或 TCP 窗口问题。

常见问题

iKuai 里勾了「使用默认网关」还是上不了网，怎么办？

按顺序查四项：一，分流策略里是否有「目的地址为国内则走主 WAN」的规则把流量抢回去了；二，MTU 是否过大，试 1400；三，隧道对端是否能 ping 通（iKuai 的系统工具里测）；四，DNS 是否还指向旧的主 WAN 的 DNS。四项里第二、四项最常见。

L2TP 必须配 IPsec 吗？

不是必须，但纯 L2TP 没有加密，只能提供隧道不提供保密。多数服务商启用 L2TP over IPsec（UDP 500/4500 做密钥协商，ESP 承载数据）。配了 IPsec 时，预共享密钥必须与服务端一致，留空会导致「拨号无响应」而不是明确报错。

为什么拨号显示已连接，但所有网站都打不开？

九成是「使用默认网关」没勾。不勾时，这条 WAN 只注册一条到对端的明细路由，默认路由仍指向主 WAN，隧道实际上只用于访问对端本身。另一个可能是隧道分配到的地址与内网网段冲突，检查对端给的地址段是否与你 LAN 段重叠。

软路由跑 L2TP，速度只有几十兆是什么原因？

三个方向：CPU 单核跑满（加密开销在单核上，查看 CPU 占用是否某个核 100%）；未开启硬件加速（iKuai 的转发加速选项）；MTU 与 TCP 窗口配合不佳导致单流受限（用多线程测速对比验证）。先看 CPU，再看加速，最后看 MTU。

分流规则怎么配才不会让国内网站变慢？

用「目的地址」维度做策略路由：国内运营商地址库 → 主 WAN 直连；其余 → L2TP。不要用「域名」维度在路由器层做（路由器看不到 HTTPS 的域名）。配完后用两个 curl 验证：不带参数应回显本地 IP，指定隧道接口应回显隧道 IP。

L2TP 会固定时间掉线，是什么问题？

两类原因：服务商的维护窗口（看掉线时间是否每天一致，向服务商核对）；运营商对长连接 UDP 的会话老化（表现为 24 小时左右必断，重拨即恢复）。后者可以在 iKuai 里开启线路检测 + 自动重拨来缓解。

能同时用两条 L2TP 做负载均衡吗？

可以做多 WAN 负载，但对同一目标站点的会话会被分散到两条链路，导致登录态异常（平台看到 IP 在跳）。养号场景不要做负载均衡，只做主备：一条主用，一条待命，主链路故障时切换。

iKuai 能不能跑 VLESS？

可以。iKuai 本身不带 VLESS 客户端，常见做法是用 Docker 跑 sing-box 或 Xray，把入站设为透明代理，再在 iKuai 里把需要代理的流量指向这个容器。配置比 L2TP 复杂，收益是抗封锁与精细分流。轻量方案是旁路由跑 OpenWrt + passwall。

电视盒子、Switch 这类设备需要单独配置吗？

不需要。L2TP 在路由器上拨号，NAT 后的所有终端自动继承，包括电视盒子、Switch、智能音箱。唯一要注意的是分流策略要按「目的地址」判断，否则会出现「盒子里的国内视频 App 也走隧道，加载变慢」。

重启软路由后不自动重连，怎么修？

检查两点：WAN 口是否设置为开机自动拨号；线路检测是否开启（部分版本在没有检测的情况下，首次拨号失败后不会重试）。另外确认配置已保存到启动项——iKuai 的部分设置在未点击「保存并应用」时只存在于内存。
