怎么判断你的 IP 干不干净？三个维度，三个工具

IP检测IP纯净度检测P1更新于 2026-11-05

判断一个IP干不干净，看三个维度。类型、历史、归属。这三个维度决定了平台怎么看你这个环境。

维度一 类型

第一个维度，类型。住宅IP大于机房IP。机房IP段被平台批量标记，注册就异常。这不是绝对的，但机房IP的成功率明显低。原因是机房IP段是公开的，平台很容易识别。

维度二 历史

第二个维度，历史。这个IP之前有没有被人用来注册过账号、发过垃圾内容。查法是打开 ipqualityscore 点 com，或者 scamalytics 点 com，输入IP看打分。

分数越低越干净。

维度三 归属

第三个维度，归属。原生IP是当地运营商直接分配的，ASN 归属当地ISP。广播IP是一个地区的IP段被广播到另一个机房使用，IP归属地显示A国，实际物理位置在B国。平台的识别方式是查ASN。

打开 ipinfo 点 io 看ASN，是运营商还是机房，一眼就看出来。

最直接的土办法

最直接的土办法，用这个IP注册一个测试账号。看要不要验证码，要不要手机号。不用验证直接能注册的IP，就是干净的。这个方法比任何工具都准，因为平台的风控模型就是最终裁判。

结论

三个维度加起来，加上一次真实注册测试，基本能判断这个IP能不能用。买之前让服务商给你测试IP，测完再付钱。不给测的，直接跳过。

为什么要分三个维度，而不是看一个评分

多数人查 IP 只做一件事：打开一个检测站，看一个百分制分数。这个做法的问题是，各家评分模型的输入不同、权重不同，同一个 IP 在三个站上可能得到「低风险、中风险、高风险」三个结论。

正确做法是把「干不干净」拆成三个正交的维度，分别查，分别判断：

  • 类型：这个 IP 是住宅、机房、移动，还是双 ISP
  • 历史：这个 IP 有没有被用来注册、发垃圾、发攻击
  • 归属：注册地、实际落地、ASN 三者是否一致

三个维度都过关，才叫干净。任何一个维度有硬伤，都要按不同方式使用（做一次性任务可以，做长期账号不行）。

维度一：类型，看 ASN 的 usage type

类型ASN 特征平台视角适合场景
住宅（ISP）当地运营商，如 HKBN、PCCW、HKT真实用户养号、长期账号
移动（Cellular）移动运营商，如 CMHK真实用户，权重最高高价值账号
双 ISP / 商业宽带小型 ISP 或商业线路中性一般业务
机房（Hosting）IDC、云厂商，AWS/GCP/阿里云高风险，常被批量标记爬虫、API 调用
匿名网络Tor、公开 VPN 出口直接拒绝不建议

查法是看 IP 的 ASN 与 usage type：

# 命令行查 ASN 归属
whois -h whois.cymru.com " -v 1.2.3.4"
# 或直接看 API
curl -s https://ipinfo.io/1.2.3.4/json

返回里重点看 `org`（组织名）和 `usage type`。组织名里出现 Cloud、Hosting、Datacenter、Server 这类词，基本可以判机房。反过来出现 Telecom、Broadband、Mobile、Communications，可判运营商。

一个判据比名字更可靠：看这个 IP 段有多少活跃的「服务端口」响应。机房 IP 段通常有大量 22/80/443 开着；住宅 IP 段几乎没有。可以做小规模抽样验证，但注意不要对非授权目标做扫描。

维度二：历史，看公开库的黑名单与评分

工具查什么干净的阈值
ipqualityscore欺诈分、代理/VPN 标记分数 < 25，无 proxy 标记
scamalytics风险分（0-100）< 20，无 vpn/tor 标记
abuseipdb滥用举报次数与置信度近 90 天 0 条，置信度 0
whoer.net黑名单、DNS 泄漏、时区一致性黑名单空
Spamhaus / DNSBL邮件与垃圾内容黑名单不在任何列表

这些库的共同局限：它们只能看到「已经被公开记录的问题」。一个刚被批量注册废掉、但还没进黑名单的 IP，在这些库里是干净的。所以历史维度只能筛掉明显脏的，不能证明干净。

维度三：归属，注册地 vs 实际落地 vs ASN

这是最容易被忽视、也最影响账号稳定性的维度。三种不一致都常见：

  1. 注册地在香港，ASN 是香港运营商，但 traceroute 第一跳在新加坡（广播）
  2. 注册地在香港，ASN 是美国某 IDC 的香港子公司（机房冒充住宅）
  3. 注册地和 ASN 都在香港，但 IP 库把这个段标成「代理/VPN」（段被同行污染）

判定流程：

# 1. 注册信息
whois 1.2.3.4 | head -30
# 2. 实际落地：从内地测 RTT 与第一跳
mtr -rw -c 20 -n 1.2.3.4
# 3. 库里的归类
curl -s https://ipinfo.io/1.2.3.4/json

一致性判据：香港 IP 从深圳测 RTT 应在 5-25ms；从上海测 25-45ms。超过这个区间，要么是广播，要么是中转绕路。

最直接的判定：注册测试

所有工具都是间接证据，平台风控才是最终裁判。所以最准的方法是拿这个 IP 去目标平台注册一个测试号。

执行细则：

  1. 用干净的无痕窗口，只改 IP，不改浏览器指纹（否则分不清是 IP 的问题还是指纹的问题）
  2. 记录是否需要图形验证码、是否需要手机、注册后是否立刻要求验证
  3. 注册成功后正常浏览 10 分钟，看是否弹出验证
  4. 用一个已知干净的 IP 做对照，两组结果对比才有意义

四种结果对应四种结论：

结果结论建议
免验证直接注册，10 分钟无弹窗干净可用于长期账号
需要一次图形验证码中等可用于一般账号，避免高价值号
需要手机验证偏差一次性任务可用
反复失败或注册即封脏换 IP，别浪费时间

IP 段污染：比单个 IP 脏更麻烦

平台的风控通常按段聚类。一个 /24 段里如果有几十个账号被标记，整段的信誉会下降。这时候你买的 IP 本身可能从没被用过，但它在脏段里，一样被降权。

判断段污染的方法：

  1. 查这个 /24 段在 abuseipdb 上的举报总量
  2. 用同段的几个 IP 分别做注册测试，结果一致差 → 段污染
  3. 查这个段的注册时间，近期集中注册的新段风险更高

遇到段污染，只能换段，不能换 IP。这是选服务商时应该问的一个问题：「你们给我的是哪个 /24，这个段有多少客户在用」。

一份可执行的检查清单

  • 查 ASN 与 usage type，确认是运营商不是机房
  • 查 ipqualityscore 欺诈分，< 25
  • 查 abuseipdb 近 90 天举报，0 条
  • 查 whoer 黑名单与 DNS 泄漏
  • 从两个不同城市 mtr，确认落地位置与声称一致
  • 查所在 /24 段的举报总量，判断段污染
  • 用目标平台做一次真实注册测试，与干净 IP 对照
  • 连续 3 天复查评分，确认没有上升趋势

八项全过，这个 IP 可以放心用。任何一项不过，按上表降级使用。

一个可复用的批量检查脚本

手工一个一个查 IP 不可持续。下面这段可以在本地跑，把一批 IP 的类型、归属、评分一次性拉出来对比（API 需要各自申请免费 key，注意免费额度）：

#!/usr/bin/env bash
# 用法: ./ipcheck.sh 1.2.3.4 5.6.7.8 ...
for ip in "$@"; do
  echo "=== $ip ==="
  # ASN 与归属
  whois -h whois.cymru.com " -v $ip" | tail -1
  # 基础信息（registry/org/城市）
  curl -s "https://ipinfo.io/$ip/json" | tr ',' '\n' | grep -E '"(org|city|country|region)"'
  # 反查是否有 PTR（住宅 IP 通常有，机房常常没有）
  dig +short -x "$ip"
done

判读口径：`org` 里出现 Cloud/Hosting/Datacenter 判机房；PTR 记录形如 `x-x-x-x.dynamic.isp.com` 多为住宅动态，形如 `static.isp.com` 多为静态住宅；完全没有 PTR 的多是机房或新段。

记录趋势比单次检测更有价值

单次评分只能说明「此刻」，趋势才能说明「正在变脏」。建议维护一张表，每个 IP 一行，每次复查记一列：

日期IP类型欺诈分举报数注册测试结果
第 1 天1.2.3.4住宅120免验证
第 7 天1.2.3.4住宅180一次图形码
第 14 天1.2.3.4住宅412需手机验证

第三行出现时，就该换 IP 了。等到注册直接失败再换，中间损失的账号成本远高于 IP 差价。

常见问题

IP 纯净度多少分算干净？

以 ipqualityscore 的欺诈分为例，25 分以下算干净，25-75 分中等（可做一般账号，避免高价值号），75 分以上不建议用于注册类操作。注意各家评分模型不同，单看一个分数不够，要结合 abuseipdb 举报记录与实际注册测试。

住宅IP一定比机房IP好吗？

对「需要像真人」的场景是。住宅 IP 的 ASN 挂在运营商名下，平台难以批量识别；机房 IP 段公开，批量标记成本低。但住宅 IP 也有代价：带宽小、稳定性依赖运营商、价格高。做数据同步、API 调用，机房 IP 更划算。

为什么同一个 IP 在不同检测站分数差很多？

因为各家模型的输入不同：有的侧重历史滥用记录，有的侧重 ASN 类型，有的侧重代理特征指纹。分数差异不代表某一家错了，只说明它们看的维度不同。判断时看「有没有硬伤」（是否在 proxy/vpn 列表、是否有近期举报），而不是比分数。

怎么查一个 IP 段的污染程度？

三步：查这个 /24 段在 abuseipdb 上的举报总量；用段内两三个 IP 分别做目标平台注册测试，看结果是否一致差；查这个段的历史（何时注册、是否近期被批量分配）。三项都指向「脏」，就换段而不是换 IP。

注册测试法具体怎么做才有效？

关键是控制变量：用无痕窗口，只换 IP，不改指纹；用一个已知干净的 IP 做对照组；记录四项结果（是否要图形码、是否要手机、注册后是否弹验证、能否正常浏览 10 分钟）。没有对照组的测试结论不可靠。

DNS 泄漏会影响 IP 纯净度判定吗？

会。IP 在香港但 DNS 请求发往国内运营商，既暴露了你不在当地，也会让 CDN 解析到错误节点。检测时看 whoer 的 DNS 泄漏项，正确状态是 DNS 服务器与 IP 在同一区域。软路由场景要在分流规则里单独指定 DNS。

时区不一致会有什么后果？

时区和语言是平台判断「环境是否伪造」的低成本信号。IP 在东京、系统时区 UTC+8、浏览器语言 en-US，三者互相矛盾，构成典型特征。正确做法是全链路一致：IP 落地城市 → 系统时区 → 浏览器语言 → 输入法。

IP 评分正常，但注册还是被要求验证，为什么？

说明平台的模型看到了公开库没记录的信息：这个 IP 段的历史行为、你使用的浏览器指纹、注册行为本身的节奏（过快、过于模板化）。此时该改的是行为与指纹，不是继续换 IP。

多久复查一次 IP 状态？

新 IP 上线后前两周每三天查一次，稳定后每月一次。重点是看趋势：评分是否在上升、abuseipdb 是否出现新举报。上升趋势说明这个 IP（或段）正在被污染，提前换比事后救便宜。

免费检测工具有哪些坑？

两类。一类是「检测即采集」：某些站点会把你的 IP、UA、时区组合记录下来，反而给你打上标记。另一类是「结论过于乐观」：只查黑名单，不查段污染与行为特征，给出的「干净」结论没有参考价值。用知名工具，且不要在同一站点高频重复检测同一 IP。
